# Gemini Merge Strategy: CrestHDRP + OpenOceanPhysics

## Summary
This is a high-performance architectural merge. **Project A** provides the rock-solid, garbage-free rendering pipeline, sphere topology, and HDRP lighting framework. **Project B** provides the heavy-duty math engine (GPU FFT, cascading, Jacobian foam).

Merging them creates a **Planet-Scale, FFT-Displaced, Spherical Ocean with HDRP Advanced Material Features**.

---

## 1. What to Keep from Each Project

### From Project A (CrestHDRP):
- **Icosphere Topology & Radial Displacement:** Keeps the planet curvature intact without UV seams at the poles.
- **MaterialPropertyBlock Pipeline:** Zero material instantiation, perfect for batching and garbage-free runtime parameter updates.
- **HDRP Custom Pass & Sky Sampling:** Essential for reflections, refraction, and volumetric integration in Unity 6 HDRP.
- **Advanced Surface Shading:** SSS (Subsurface Scattering), analytic caustics, and crisp Fresnel calculations.
- **Buoyancy & Architecture:** Clean, reviewed, production-ready C# code structure and Editor Wizards.

### From Project B (OpenOceanPhysics):
- **Compute Shader FFT Engine:** The heart of the wave displacement (multi-cascade Phillips/JONSWAP spectrum evaluated via Fast Fourier Transform).
- **Jacobian Foam & Shore Foam:** Physics-driven foam generation based on wave pinching/stretching (Jacobian determinant) and distance-to-terrain depth.
- **Burst Job Gerstner Layer:** High-frequency choppy wave details added on top of the low-frequency FFT displacement.

---

## 2. What Overlaps and Should Be Merged

| Feature | Project A | Project B | Merge Strategy |
| :--- | :--- | :--- | :--- |
| **Wave Spectrum** | JONSWAP (Analytic) | Phillips/JONSWAP (Compute/FFT) | **Use B's Spectrum generation** inside the compute shaders, but keep A's inspector controls exposed via PropertyBlocks. |
| **Foam Generation** | Analytic wave crest approximation | Jacobian + Shoreline proximity | **Combine them:** Use B's Jacobian foam (mid/near) + Shore foam, augmented by A's aesthetic tweaks. |
| **Displacement Source** | Radial displacement via Analytic math | GPU FFT + Gerstner | **Hybrid Displacement:** Compute Shader FFT handles large/medium scales; Burst Gerstner handles micro-choppiness. Both are fed into the Icosphere vertex/pixel shader. |

---

## 3. What is Unique and Should Be Added

- **Distance-Based Cascade Blending (from B):** As the camera moves away from the planet/ocean surface, seamlessly blend out high-frequency FFT cascades to prevent shimmering/aliasing.
- **HDRP SSS + FFT Normals (Combination):** Apply Project A's SSS and refraction lighting model to the dynamic normal maps generated by Project B's FFT compute buffers.

---

## 4. Step-by-Step Merge Plan

### Phase 1: Foundation & Structuring
1. Create a new repository/project combining directories: `Assets/CrestHDRP/` (Base) and `Assets/OpenOceanPhysics/` (Compute/FFT modules).
2. Ensure Unity 6 HDRP settings are active and the Custom Pass infrastructure from Project A is preserved.

### Phase 2: The Wave Engine (Compute & Burst)
1. Move OpenOceanPhysics Compute Shaders (`FFTGeneration.compute`, `CascadeBlend.compute`) into `CrestHDRP/Shaders/Compute/`.
2. Adapt Project B's C# FFT Manager to write into global compute textures (`Texture2DArray` or individual cascade RTs) rather than a flat plane.
3. Keep Project B's Burst Job Gerstner system as a secondary high-frequency vertex offset generator.

### Phase 3: The Icosphere + FFT Vertex Shader
1. Modify Project A's icosphere vertex shader (HLSL) to sample the FFT displacement textures from Project B.
2. *Crucial Adjustment:* Because Project A uses a **spherical** icosphere, standard planar FFT UV mapping will distort. You must calculate FFT UVs based on spherical projection coordinates (e.g., latitude/longitude or projected cube-map style coordinates from the sphere center) rather than flat XY plane coordinates.

### Phase 4: Material & Foam Integration
1. Inject Jacobian foam and Shore foam data from the compute pipeline into Project A's `MaterialPropertyBlock`.
2. Update Project A's uber-shader (`CrestOceanHDRP.shader`) to blend FFT normals, Jacobian foam, SSS, and caustics.

### Phase 5: Buoyancy & Polish
1. Update Project A's radial buoyancy system to sample *both* the FFT compute textures and the Burst Gerstner waves so objects float accurately on the combined wave surface.
2. Clean up garbage collection, verify zero allocations in the main loop, and test under Unity 6 HDRP profile.

---

## 5. Potential Conflicts and How to Resolve Them

### Conflict 1: Planar FFT vs. Spherical Icosphere
- **Problem:** FFT compute shaders natively assume a flat 2D grid (X, Z). Project A is a sphere. Flat FFT projected onto a sphere will pinch at the poles.
- **Resolution:** Use a **tangent-space local projection** for the FFT cascades centered around the camera, or map the FFT textures across a cubemap layout matching the icosphere's radial distribution. For a local ocean view, local planar projection relative to the camera position on the sphere works best.

### Conflict 2: Shader Integration (HLSL Include Hell)
- **Problem:** Project A uses custom HDRP includes for Custom Passes and SSS; Project B uses its own HLSL files for wave math.
- **Resolution:** Create a single master include file: `CrestOceanData.hlsl`. Centralize all struct definitions, FFT sampling functions, and Gerstner math here. Include this single file in both the Icosphere surface shader and the HDRP Custom Pass.

### Conflict 3: Property Management
- **Problem:** Project A uses `MaterialPropertyBlock` exclusively; Project B's compute shaders rely heavily on global shader properties (`Shader.SetGlobalFloat/Vector`).
- **Resolution:** Hybridize cleanly. Use **Global Shader Properties** for compute shader parameters (cascade scales, wind direction, time) because compute shaders cannot read MaterialPropertyBlocks easily. Use **MaterialPropertyBlocks** per-renderer for static material tweaks (base color, tint, roughness).
